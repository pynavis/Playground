# Changelog

All notable changes to pyNavis Playground, newest first. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the numbers follow
[Semantic Versioning](https://semver.org/). The number in each heading is the one in
`VERSION`, `catalog.json` and the release zip's download link.

Status changes of single tools are not listed here: `status.yaml` is their history.

## [0.1.0] - Unreleased

### Added

- The first public cut of pyNavis Playground: 140 experimental tools for pyNavis in five
  tabs (Model, Views, Coordinate, Project, Dev), built on namo, the Playground library.
- `status.yaml`, the status ledger: `untested`, `launched`, `verified` or `known-issue`
  per tool, each with a date and the kind of evidence behind it.
- `catalog.json`, generated by `tools/build_catalog.py`: every tool with its tab, panel,
  summary, status, the feature-list row it answers, the hook events it needs, its files,
  its stack siblings and, where one was found, the public user ask behind it.
- `tools/package.py`: the release zip `Playground.extension.zip`, with
  `status: experimental` stamped into every tool's `bundle.yaml`, and its SHA-256 in the
  catalog.
- PlaygroundLink, a small pyRevit companion extension for Show in Revit and Send to
  Navisworks.
- `dev/verify.py`, the headless checks every change must pass, and `dev/runner`, a harness
  that runs each tool under `pynavis run` on a sample model; `dev/runner/RESULTS.md`
  records the first full pass and what it can and cannot show.
- `SECURITY.md`: what the in-app installer checks and where it writes.
- The public catalog site at https://pynavis.github.io/Playground/, generated into `docs/`
  from `catalog.json` by `tools/build_site.py`: an index with a status summary, a filter by
  text and status, and every tool by tab and panel; one page per tool with its status and
  evidence, the public ask behind it, its stack siblings, hooks and files, how to install
  it, and a link to report back. `--check` keeps it current, and `dev/verify.py` runs it.
- `status_by` in `catalog.json`: the kind of evidence behind each status (`log`, `runner`
  or `person`), from the ledger's `by` field.
